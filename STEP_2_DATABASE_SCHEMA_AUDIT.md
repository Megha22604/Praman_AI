## 9. Data With No Current Destination

The following items produced by `/api/scan-image` have **no corresponding column** in the current database schema:

1. `detected_raw_lines` / `raw_lines` (`list[str]`) — No raw OCR text column in `scans` or `scan_results`.
2. `package_height_cm` & `package_width_cm` (`float`) — Package physical dimensions are not stored in `scans`.
3. `compliance_report.score` (`str`) & `percentage` (`float`) — Overall compliance score string (e.g. `"7/8"`) and percentage score (`87.5`) have no columns in `scans`.
4. `pass_count`, `review_count`, `fail_count`, `total_count` (`int`) — Summary counter fields are not stored in `scans`.
5. `item.confidence` (`float`) — Individual rule confidence score has no column in `scan_results`.
6. `misleading_declarations` (`dict`) — Advisory non-standard / misleading claims object has no column or table.
7. `item.field` (`str`) — Human-readable rule title (e.g. `"MRP"`, `"Net Quantity"`) has no column in `scan_results`.

---

## 10. Schema Compatibility Problems

1. **`products.name` `NOT NULL` Constraint:** Inserting a `scan` associated with a new product requires a record in `products`. However, `products.name` is marked `NOT NULL`, while `/api/scan-image` does not accept a product name in its request inputs.
2. **Missing `confidence` Column:** `scan_results` cannot persist the confidence score generated by `rules_engine.py`.
3. **Loss of Raw OCR Text:** `raw_lines` is discarded upon DB insertion unless stored in an unmapped column or JSON array.
4. **Loss of Summary Analytics & Misleading Claims:** Analytical metrics (`score`, `percentage`, counts) and `misleading_declarations` cannot be persisted in dedicated columns.
5. **Image URL Handling:** `images.image_url` is `NOT NULL`, but `/api/scan-image` processes raw file bytes in memory without saving them to storage.

---

## 11. Recommendations for Next Step

> [!NOTE]
> Recommendations strictly preserve the read-only policy and outline future backend integration steps.

1. **Default / Fallback Context Handling:** In the future persistence layer, handle optional `product_name`, `user_id`, and `org` using fallback defaults (e.g., linked to default `products` and `users` records) when not provided in the API request.
2. **Result Batch Mapping:** Map each item in `compliance_report.results` to individual `scan_results` rows (`rule_code`, `status`, `finding_detail`).
3. **Local File / Storage Path Generation:** Generate a local storage relative path or file reference for uploaded images to satisfy `scans.image_url` and `images.image_url`.
4. **Graceful Handling of Unmapped Data:** Keep unmapped analytics (`raw_lines`, `misleading_declarations`, `confidence`) in the API response while persisting core relational columns in PostgreSQL.
